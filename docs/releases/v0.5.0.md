# OctoRunner v0.5.0

Settings, job history, and host diagnostics for self-hosted GitHub Actions runners.

## What's New

- Six settings categories available from the main window or via `⌘,`, with search, readable cards, and responsive layouts: General, Autostart & Background, Failover, Cache & Storage, Auth & Tokens, and Notifications.
- Login item, Dock, and language settings. Newly created LaunchAgents use the configured shell, PATH, and restart policy. Settings shows version information and offers an on-demand check for stable updates.
- Opt-in native macOS notifications for local online and offline transitions, detected new job failures, and low disk space. Each event can be enabled separately.
- Job history with filters, per-account isolation, paginated details, current queue state, and metrics for loaded data. Runner state and the last job result appear separately. Active jobs show a blue **Running** status.
- Safe cache and storage analysis, a cleanup preview, and log retention for managed runner directories. Cleanup is scoped to managed paths.
- An audit dialog with category, severity, and runner filters and export. Historical runner names remain available in the filter.
- Host telemetry for CPU, RAM, memory pressure, thermal state, I/O, and the observed GitHub API budget. The process inspector shows CPU, RAM, and uptime, and can terminate an identified runner process after confirmation.
- A menu bar logo with runner status, improved resizing for the dashboard and runner wizard, and built-in help for `GITHUB_WORKSPACE` and `RUNNER_WORKSPACE`.
- More robust account and Keychain handling and checksum verification for runner downloads. Startup leaves Documents access untouched.
- Fixed blocking HTTP test server cleanup and a premature Dock activation policy change on the first native UI launch. Test runs now have time limits and stack diagnostics. Closed standard output no longer causes a busy loop.
- GitHub PR matching with an optional read-only commit lookup, workflow details per run attempt, expandable jobs and steps, and on-demand UTF-8 job logs capped at 1 MiB. Direct PR, run, and job links remain available.

## Scope and Limits

Global runner concurrency, full supervision with crash and quarantine policies, live log streaming, transactional migration, and periodic GitHub reconciliation follow in v0.6. That milestone includes enforcement of the concurrency limit. Changed settings apply to newly created LaunchAgents. Updating an existing service requires an explicit change.

Notifications and central monitoring run while the GUI is active. Installed LaunchAgent runners can continue after the app quits. A separate background agent is optional future work. Crash notifications require process supervision and remain disabled in this release.

Jobs metrics cover loaded history. CPU topology shows performance and efficiency core counts, and I/O measurements cover host devices. Missing measurements and unknown token permissions are labeled as such. Full localization and accessibility acceptance and stronger update rollback are planned for v0.7.

## Installation and Acceptance

Apple Silicon and macOS 15 or later are required. Install the current stable version with `brew install --cask loesch-digital/tap/octorunner`. To install this version directly, extract the signed, notarized ZIP from the release assets and open the app in Finder with quarantine attributes intact. [Homebrew Tap](https://github.com/loesch-digital/homebrew-tap) · [Xcode acceptance guide](https://github.com/loesch-digital/octorunner/blob/main/docs/10-development-and-acceptance.md)

Debug, beta, and stable builds share the database, preferences, and Keychain. Use a separate macOS test user and test runners for isolated changes.

1. Open Settings, check the desired options, and run an update check. Enable notifications if needed.
2. Filter Jobs by repository and Audit Log by runner. Check the current runner state and the last job result.
3. Open Telemetry, inspect process details, and resize the window.

Local verification before the PR passed 330 Swift tests in 67 suites, 33 Python tests, and a native Xcode app build. Native UI tests, signing, notarization, the Homebrew tap, and local Gatekeeper verification have separate CI and release gates.
