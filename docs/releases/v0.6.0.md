# OctoRunner v0.6.0

Start and supervise managed runners, migrate existing runners safely, and reconcile registrations with GitHub.

## Runner Operations

- Start, stop, and restart managed runners. Process supervision detects unexpected exits and applies restart rules, delays, and quarantine. The global concurrency limit applies to runners launched directly by OctoRunner.
- The local console streams new log output. The current runner state and the last job result appear separately.
- Migration checks the local listener, GitHub identity, labels, and organization group. Before confirmation, it shows the source, destination, and planned changes. Stop the old listener and disable its existing startup mechanism first. Saved recovery information helps if migration is interrupted.

## GitHub

- Periodic reconciliation shows both local and GitHub-reported states and flags confirmed differences. Label changes can be applied in either direction after confirmation and are recorded in the audit log.
- The wizard sets up multiple repositories with separate registrations. A shared name prefix helps identify related runners. A GitHub label controls workflow routing through `runs-on`.
- For organizations, the wizard shows available runner groups. Inspect saved group membership in runner settings. In **Settings → Auth & Tokens**, select **Check Runner Permissions** to check the active account's read access for each target.

## Installation and Acceptance

OctoRunner requires Apple Silicon and macOS 15 or later. Install the current stable version with `brew install --cask loesch-digital/tap/octorunner`. The signed ZIP for this release is available from GitHub Releases for direct installation. Development builds can run directly in Xcode. [Homebrew Tap](https://github.com/loesch-digital/homebrew-tap) · [Xcode acceptance guide](https://github.com/loesch-digital/octorunner/blob/main/docs/10-development-and-acceptance.md)

1. Select several test repositories in the runner wizard and verify the targets, instance count, and name preview. For a test organization, compare the available groups with GitHub.
2. Start, stop, and restart a managed test runner and verify live log output. After a failed job, check the last job result and the current runner state.
3. In Auth settings, check access to the saved targets. Migrate a disposable runner under a test account.

Quitting the GUI stops periodic GitHub reconciliation. Installed LaunchAgents can continue running. The GUI supervises runners it starts directly.
