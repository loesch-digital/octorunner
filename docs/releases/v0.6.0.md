# OctoRunner v0.6.0

Verwaltete Runner starten und überwachen, bestehende Runner sicher übernehmen und ihre Registrierung mit GitHub abgleichen.

## Runner-Betrieb

- Start, Stopp und Neustart für verwaltete Runner. Die Prozessaufsicht erkennt unerwartete Exits und berücksichtigt Neustartregeln, Wartezeiten und Quarantäne. Das globale Parallelitätslimit steuert direkt von OctoRunner gestartete Runner.
- Die lokale Konsole liest neue Logausgaben fortlaufend. Der aktuelle Runner-Status und das Ergebnis des letzten Jobs bleiben getrennt.
- Die Migration prüft lokalen Listener, GitHub-Identität, Labels und Organisationsgruppe. Vor der Bestätigung zeigt sie Quelle, Ziel und geplante Änderungen. Der alte Listener samt bisherigem Autostart muss gestoppt sein. Bei einer unterbrochenen Migration helfen gespeicherte Wiederherstellungsinformationen.

## GitHub

- Der periodische Abgleich zeigt lokale und von GitHub gemeldete Zustände und markiert bestätigte Unterschiede. Bestätigte Labeländerungen sind in beide Richtungen möglich und werden protokolliert.
- Der Assistent richtet mehrere Repositories mit getrennten Registrierungen ein. Ein gemeinsames Namenspräfix erleichtert die Zuordnung. Ein GitHub-Label steuert die Job-Auswahl über `runs-on`.
- Für Organisationen zeigt der Assistent verfügbare Runner-Gruppen an. In den Runner-Einstellungen lässt sich die gespeicherte Gruppenmitgliedschaft prüfen. Unter **Einstellungen → Auth & Tokens** prüft **Runner-Berechtigungen abgleichen** den Lesezugriff des aktiven Kontos je Ziel.

## Installation und Abnahme

OctoRunner benötigt Apple Silicon und macOS 15 oder neuer. Installation mit `brew install --cask loesch-digital/octorunner/octorunner`, Upgrade mit `brew update && brew upgrade --cask octorunner`. Für die Installation ohne Homebrew steht das signierte ZIP in den GitHub Releases bereit. Ein Entwicklungsstand lässt sich direkt aus Xcode starten. [Abnahme aus Xcode](../10-development-and-acceptance.md)

1. Im Runner-Assistenten mehrere Test-Repositories auswählen und Ziel, Instanzanzahl und Namensvorschau kontrollieren. Für eine Testorganisation die angebotenen Gruppen mit GitHub vergleichen.
2. Bei einem eigenen verwalteten Test-Runner Start, Stopp, Neustart und fortlaufende Logausgabe prüfen. Bei einem fehlgeschlagenen Job den letzten Jobstatus getrennt vom Runner-Status kontrollieren.
3. In den Auth-Einstellungen den Zugriff auf die gespeicherten Ziele abgleichen. Eine Migration mit einem entbehrlichen Runner unter einem Testkonto durchführen.

Die GUI beendet beim Quit den periodischen GitHub-Abgleich. Installierte LaunchAgents können weiterlaufen. Direkt gestartete Runner unterliegen der Prozessaufsicht der GUI.
