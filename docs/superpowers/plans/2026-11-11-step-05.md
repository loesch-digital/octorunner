# Settings, Jobs, Telemetry, and Audit Implementation Plan

> **Scope updated November 19, 2026.** The user moved the global concurrency limit to v0.6. That decision supersedes earlier references to v0.5 in this plan. See [Remaining Delivery Plan](../../18-remaining-delivery-plan.md) for current progress and follow-up plans.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal** — Deliver the requested Step 5 as a working v0.5.0 release.

**Architecture** — Persist preferences on MainActor and use injectable services and actors for system integration and file operations. Keep SwiftData models on their own ModelContext. The API and telemetry produce Sendable values. The native Settings scene, existing dashboard, and new Jobs, Telemetry, and Audit views share services.

**Tech stack** — macOS 15+, Swift 6 strict concurrency, SwiftUI, SwiftData, ServiceManagement, UserNotifications, Mach, libproc, IOKit, and Foundation URLSession. Use existing external dependencies.

**Spec** — The user request, `docs/07-step-05-settings-telemetry-and-jobs.md`, and section 4 of `docs/01-architecture-and-modules.md`. The user authorized implementation of the existing design and reasonable adaptations to the reference screens.

## Global Constraints

- Use the dedicated branch `feat/step-05-settings-jobs-telemetry`, semantic commits, and a PR. Require all PR and main CI checks to pass before release.
- Start with a failing test using `swift test --package-path Packages/OctoRunnerKit --no-parallel`, then implement the change and make it pass. The Python suite must also pass.
- Apply the four repo skills and relevant references. Keep the macOS 15 deployment target.
- Provide six Settings tabs: General, Autostart & Background, Failover, Cache & Storage, Auth & Tokens, and Notifications.
- Give new controls accessibility labels and hints, use OctoTheme, and test contrast in Light and Dark appearances.
- Store secrets only in Keychain and keep them out of audit entries, exports, and logs.
- Require explicit permission for external folder access and avoid following external symlinks. Request access only when a specific operation requires it.
- Give all SwiftData properties defaults. Preserve SQLite header validation and makeInMemoryContainer. Keep models on their own actor and check cancellation before model access.
- Xcode 27.2 and Swift 6.4.2 were verified at the time of writing. Use stable dependencies and guard APIs above the deployment target with availability checks.
- Release v0.5.0 after Step 5 acceptance. v0.6.0 adds full crash and quarantine supervision, migration, and sync. Stop at the final planned release, v0.7.0.

## Review Focus

1. Fall back to safe values for invalid or corrupt preferences. Show failed system registrations accurately in the UI.
2. On cancellation or an account switch, discard old request data and keep credentials on the intended host during pagination.
3. Protect active jobs, unmanaged paths, symlinks, and GitHub Runner binaries during workspace and log cleanup.
4. Handle empty history, retries and run attempts, paginated responses, and missing runner matches without duplicates or unsupported SLA metrics.
5. Use measured telemetry. Show the first CPU and I/O sample and unavailable measurements as unknown. Recheck process identity before taking action to protect unrelated processes when a PID is reused.

## Approved Changes to the Historical Screens

- Support fine-grained PATs, display only permissions GitHub actually reports, and omit the `workflow` scope from requirements.
- Use SMAppService.mainApp for local login items. The scope is local startup with standard user privileges. Keep Pro and remote failover inactive.
- Show thermal state and memory pressure separately. Report available CPU topology and measured CPU and VM data. Leave individual tool memory and performance- and efficiency-core load unavailable when attribution is unreliable.
- Default to manual pruning. Automatic modes apply only to app-managed runners with a fresh, safe idle state. Require separate user selection and confirmation for host caches.
- Apply shell and concurrency settings to managed starts. Let active jobs finish when limits change. Basic startup and drain integration is a Step 5 prerequisite. Full crash detection and quarantine are Step 6 work.
- Show token metadata and reuse the secure authentication flow for rotation and account switches.
